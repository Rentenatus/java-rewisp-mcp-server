# Review: read/lifecycle tools (rewisp, package de.jare.rewisp.tools)

> **Historical review status 2026-10-25 (note from 2026-11-23):** paths refer to the single-module layout of that time (`src/main/java/de/jare/rewisp/tools/...`); since 2026-11-18 the tools live in `src_mcp`. Deleted tools (`find_unreachable_code` etc.) no longer exist. Current state: [../ARCHITEKTUR.md](../ARCHITEKTUR.md) (sections "Package overview" and "Module boundary").

Scope: 25 files (BaseReadTool ... UnloadJavaProjectTool, TypeInfo), context docs/BUGS.md + docs/API-REFERENCE.md.
Known bugs #11/#14/#15/#16 are not reported again; where a finding shows a new facet of them, it is noted.
Paths relative to `src/main/java/de/jare/rewisp/` (tools = `tools/`).

## Short answers to the review questions

* **Spoon layer does not read directly from the filesystem:** in the read tools there is no `Files.*`/`new File` (the hits in `BaseReadTool` are only Javadoc text). `FileAccessService` is used by nobody (R-20). ONE indirect violation: `CheckProjectDirtyTool` calls `PomUtils.resolveParentPomPath` (does `Files.exists`/`Files.readString`), lines 246, 335, 345 (R-28).
* **Tool names vs. API-REFERENCE:** all 18 lifecycle/Spoon tools are registered under the documented name (`JavaMcpServer.java:223-241`). API-REFERENCE contains no parameter schemas, so a schema comparison is only possible against the tool descriptions. Three more tool classes (find_deprecated_usages/find_unused_code/find_unreachable_code) are NOT registered (R-19).
